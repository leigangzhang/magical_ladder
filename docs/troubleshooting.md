# 故障排查

## 1. 多台设备“单独都能用，同时开就周期性断网/丢包/很慢”

**最常见根因：两台设备用了同一把私钥（和/或同一个隧道 IP）。**
服务端把它们的流量都当作同一个 peer，谁的握手后到达就以谁为准，于是：

- 端点（endpoint）在两个端口之间来回跳；
- 握手变成每 10~30 秒一次（正常约 120 秒一次）；
- 每次重协商都作废另一台设备刚建立的会话 → 周期性全断。

**判断**：服务端 `wg show`，观察目标 peer 的 `endpoint` 是否频繁跳变、`latest handshake` 是否频繁刷新。

**修复**：每台设备一把**唯一私钥**、一个**唯一隧道 IP**。本项目用 `add-client.sh` 天然保证这一点。若此前是复制配置搭的，请用 `--import-private` 或重新 `add-client` 后重导设备。

## 2. 挂着不动一段时间后掉线 / 首包很慢

位于 NAT 或运营商大内网（CGNAT）后的设备，UDP 映射会超时被清掉。加上：

```ini
PersistentKeepalive = 25
```

本项目模板已默认带这行。

## 3. 上网很慢、部分应用卡住，但 ping 通

多半是 **IPv6 黑洞**：客户端配了 `::/0`，但 VPS 没有公网 IPv6 出口。把客户端 `AllowedIPs` 改成只有 `0.0.0.0/0`（并去掉隧道 IPv6 `Address`）。

## 4. 大包 / 视频卡顿，小包正常

MTU 偏大导致分片或黑洞。把两端 MTU 降到 1280 试：

```ini
# 客户端 [Interface] 内
MTU = 1280
```

服务端 `wg0` 亦可用 `ip link set wg0 mtu 1280` 或模板里调整。

## 5. 同时大流量下载就都变慢

共享带宽上限所致（例如 20Mbps）。VPN 本身没问题，属物理限制；可考虑限速或错峰。留意缓冲膨胀（bufferbloat）会让延迟同步飙升。

## 6. 走“加速/CDN 线路”的 VPS 上 UDP 隧道周期性抖动

部分中转/加速线路对同一目标的并发 UDP 流处理不佳，或 UDP 会话超时短。缓解：加大 `PersistentKeepalive`（如 15~20 秒）、必要时换 TCP 类隧道或更换线路。

## 7. macOS 全隧道下，连 VPS 公网 IP 却走了隧道（回环）

macOS 的 WireGuard 客户端对“到 Endpoint 自身”的路由处理因客户端而异；`route -n get <公网IP>` 若显示走 `utun`，说明到 VPS 公网 IP 的流量也被卷进隧道、在服务端“绕一圈”回来。通常能工作但会增加一跳延迟；若因此无法连接，给该公网 IP 加一条经物理网关的 /32 例外路由。

## 通用三板斧

```bash
wg show                 # 看握手、endpoint、transfer
./scripts/show-peers.sh # 看设备名映射后的状态
ping <对端隧道IP>        # 从一侧 ping 另一侧定位是“发不出”还是“回不来”
```
